# Работа и основные механизмы расширения

## Назначение

ChatGPT Context Saver - Chrome-расширение Manifest V3 для сохранения текущей беседы ChatGPT в файл. Основной сценарий: пользователь открывает чат на `chatgpt.com` или `chat.openai.com`, нажимает кнопку расширения, выбирает формат и получает экспорт в TXT, Markdown, PDF или EPUB.

Расширение не обращается к API OpenAI и не получает данные из внутреннего хранилища ChatGPT. Оно работает только с DOM уже открытой страницы браузера, поэтому качество экспорта напрямую зависит от текущей структуры страницы ChatGPT и того, какие сообщения доступны или могут быть смонтированы при прокрутке.

## Компоненты

### `manifest.json`

Manifest объявляет расширение как MV3 и задает:

- `content_scripts` для `https://chatgpt.com/*` и `https://chat.openai.com/*`;
- порядок загрузки `content/extractor.js`, затем `content/content.js`;
- popup UI в `popup/popup.html`;
- минимальный background service worker;
- permissions `activeTab`, `downloads`, `scripting`;
- host permissions только для доменов ChatGPT.

Такой набор разрешений достаточно узкий: расширение получает доступ к активной вкладке ChatGPT, может доинжектить свои скрипты и запускать скачивание файлов.

### `content/extractor.js`

Это главный слой извлечения. Он оформлен как универсальный модуль: экспортируется и в `window.ChatGPTContextSaverExtractor` для браузера, и в `module.exports` для Node-тестов.

Основные функции:

- определяет заголовок чата через `document.title`, активный элемент боковой панели или `main h1`;
- находит сообщения по `[data-message-author-role]`;
- нормализует роли только к `user` и `assistant`;
- извлекает текст из `.markdown`, `[data-message-content]`, prose/whitespace контейнеров или самого message element;
- удаляет очевидные элементы управления: SVG, form/input, copy/feedback/share/voice controls, screen-reader-only элементы;
- сохраняет полезный текст внутри text-bearing `button` / `role="button"` путем разворачивания содержимого, а не полного удаления;
- переводит HTML-структуру в Markdown-like текст: заголовки, ссылки, жирный/курсив, inline code, fenced code blocks, списки;
- нормализует часть символов-стрелок в ASCII-аналоги для более стабильного PDF-вывода;
- имеет fallback-извлечение через `article[data-testid^="conversation-turn"]`, `main article` и эвристику чередования ролей.

Самая важная часть - `extractAllMessagesWithScroll()`. ChatGPT может виртуализировать длинные беседы, оставляя в DOM только часть сообщений. Поэтому расширение:

1. Сохраняет начальный снимок сообщений.
2. Находит ближайший scrollable ancestor первого сообщения, а не просто самый высокий контейнер страницы.
3. Запоминает исходную позицию прокрутки.
4. Прокручивает контейнер к началу.
5. Снимает DOM-снимки сообщений по мере движения вниз.
6. После каждого программного scroll ждет DOM quiescence через `MutationObserver`, чтобы дождаться React/virtualizer updates.
7. Мержит последовательные снимки по overlap-логике.
8. Использует стабильные ключи из `data-message-id` или `data-testid^="conversation-turn"`, когда они есть.
9. Всегда выполняет bottom stabilization pass, даже если пользователь изначально был не внизу.
10. Считает bottom стабильным только после 3 последовательных одинаковых состояний: message count, last stable message key и `scrollHeight`.
11. После стабилизации делает финальный bottom snapshot и merge.
12. Если доступны числовые `conversation-turn-N`, проверяет gaps и ограниченно повторяет scan.
13. Возвращает скролл пользователя в исходную позицию.
14. Если пользователь был около низа, повторно мержит восстановленный bottom viewport и начальный снимок.

Это не просто чтение видимого DOM: это активный скан виртуализированного списка.

### `content/content.js`

Это тонкий bridge между popup и extractor. Он подписывается на `chrome.runtime.onMessage` и обрабатывает:

- `extractMessages` - вызывает `extractAllMessagesWithScroll()` и возвращает массив сообщений;
- `getChatInfo` - возвращает заголовок и количество видимых message groups;
- `getChatTitle` - возвращает только заголовок.

Listener возвращает `true`, чтобы Chrome не закрыл асинхронный канал ответа раньше времени.

### `popup/popup.html`

Popup содержит:

- поле имени файла;
- выбор формата `txt`, `md`, `pdf`, `epub`;
- кнопку сохранения;
- статусную область;
- локальные runtime-скрипты: `pdfmake`, custom VFS fonts, `epub.js`, `popup.js`.

Скрипты не грузятся с CDN, что соответствует требованиям расширений и текущей политике проекта.

### `popup/popup.js`

Это слой пользовательского сценария и генерации файлов.

При открытии popup:

1. Определяет активную вкладку через `chrome.tabs.query`.
2. Проверяет, что вкладка похожа на ChatGPT.
3. Запрашивает `getChatInfo` у content script.
4. Если content script не отвечает после reload расширения, доинжектит `content/extractor.js` и `content/content.js` через `chrome.scripting.executeScript`.
5. Формирует имя файла: `<title_latin>_<YYYY-MM-DD>_<N>msg`.

При нажатии "Сохранить чат":

1. Блокирует кнопку и показывает статус.
2. Запрашивает у content script `extractMessages`.
3. Проверяет ошибки и пустой результат.
4. Санитизирует имя файла.
5. В зависимости от формата:
   - TXT/MD: вызывает `formatContent()`, создает текстовый Blob и скачивает его;
   - PDF: строит pdfmake document definition и скачивает PDF Blob;
   - EPUB: вызывает `window.ChatGPTContextSaverEpub.createEpubBlob()`.
6. Скачивание для всех форматов идет через `chrome.downloads.download({ saveAs: true })`.

TXT и Markdown сейчас получают одинаковую Markdown-like структуру с заголовком экспорта, датой, количеством сообщений, ролями и разделителями. Отличие - расширение файла и MIME type: для `.md` используется `text/markdown;charset=utf-8`.

PDF-вывод строится из уже извлеченного Markdown-like текста. `popup.js` парсит:

- fenced code blocks;
- headings;
- Markdown links;
- bold/italic;
- inline code;
- эмодзи через разбиение текста на Roboto/NotoEmoji сегменты.

Сообщения выводятся цветными блоками: пользователь и ассистент имеют разные цвета role label и фона.

### `popup/epub.js`

EPUB-экспорт реализован без runtime-зависимости. Модуль:

- генерирует EPUB 3 структуру;
- создает `mimetype`;
- создает `META-INF/container.xml`;
- создает `OEBPS/content.opf`;
- создает `OEBPS/nav.xhtml`;
- создает `OEBPS/chat.xhtml`;
- создает `OEBPS/styles.css`;
- собирает ZIP-контейнер вручную без сжатия;
- считает CRC32;
- экранирует XML/HTML;
- пропускает в ссылках только `http:`, `https:` и `mailto:`, остальные URL заменяет на `#`.

Использование несжатого ZIP допустимо для EPUB и заметно упрощает реализацию в Manifest V3 runtime.

### `background/background.js`

Service worker минимальный: только логирует установку/обновление через `chrome.runtime.onInstalled`. Основной export-flow через background не проходит.

## Поток данных

```text
Пользователь нажимает кнопку в popup
        |
        v
popup.js определяет активную вкладку ChatGPT
        |
        v
chrome.tabs.sendMessage({ action: "extractMessages" })
        |
        v
content.js вызывает extractor.extractAllMessagesWithScroll()
        |
        v
extractor.js сканирует DOM и при необходимости прокручивает conversation viewport
        |
        v
content.js возвращает [{ role, content }]
        |
        v
popup.js форматирует TXT/MD, PDF или EPUB
        |
        v
chrome.downloads.download(saveAs: true)
        |
        v
Файл сохраняется пользователем на диск
```

## Ключевые инженерные решения

### DOM-first extraction

Расширение не зависит от внутренних API ChatGPT. Это снижает риск нарушения приватных API и упрощает установку, но переносит всю сложность на DOM-селекторы и эвристики.

### Scroll-aware extraction

Для длинных чатов обычный `querySelectorAll()` по DOM недостаточен. Реализация учитывает виртуализацию: сообщения собираются серией снимков во время программной прокрутки. Это сильная сторона проекта и главный механизм надежности.

После исправления потери последних сообщений скан больше не полагается только на фиксированную задержку после scroll. Он ждёт quiescence наблюдаемого DOM, затем выполняет обязательную стабилизацию нижней границы и финальный snapshot. Это закрывает сценарий, где scroll уже достиг `scrollHeight`, но последние `conversation-turn-*` ещё не смонтированы.

### Snapshot merge вместо глобальной дедупликации

Глобальная дедупликация по `role + content` опасна: пользователь может несколько раз отправить одинаковую реплику, например "continue". Текущая merge-логика пытается сохранять порядок через overlap между соседними viewport-снимками и использует стабильные DOM-идентификаторы при наличии.

### Runtime без сборки

Проект не использует bundler. Все runtime-библиотеки лежат в `lib/`, а JS подключается напрямую. Это делает расширение простым для локальной загрузки в Chrome, но требует ручной дисциплины при обновлении библиотек и шрифтов.

### PDF/EPUB из промежуточного Markdown-like текста

Extractor сначала приводит HTML ChatGPT к тексту с Markdown-подобной разметкой, а PDF/EPUB уже парсят этот промежуточный формат. Это дает единый pipeline, но означает, что экспорт не является точной HTML-копией страницы.

## Ограничения и риски

### Зависимость от DOM ChatGPT

Главный риск - изменение верстки ChatGPT. Селекторы вроде `[data-message-author-role]`, `.markdown`, `[data-testid^="conversation-turn"]` могут измениться. В проекте есть fallback, но он эвристический и может ошибаться с ролями или границами сообщений.

### Программная прокрутка страницы

Во время экспорта длинного чата расширение прокручивает conversation container. Оно старается восстановить исходную позицию, но пользователь может визуально заметить движение, а при изменениях виртуализатора ChatGPT восстановление или полнота сбора могут ухудшиться.

### Текстовый характер экспорта

Текущая реализация сохраняет текст, Markdown-структуру, ссылки, списки и code blocks. Изображения и другие rich media не сохраняются как вложения в PDF/EPUB. Если пользователь ожидает визуально точную копию чата, это нужно считать отдельной задачей.

### Markdown-парсинг ограничен

Парсинг Markdown в PDF и EPUB реализован локальными regex/line-based функциями. Он покрывает базовые элементы, но не является полноценным Markdown parser. Сложные вложенные конструкции, таблицы, footnotes, HTML внутри Markdown и нестандартная разметка могут быть упрощены.

### PDF-шрифты и эмодзи

PDF опирается на pdfmake, Roboto и Noto Emoji VFS. Эмодзи разделяются regex-ом на отдельные сегменты. Это практично, но не гарантирует корректную отрисовку всех Unicode sequences, skin tone modifiers и сложных emoji ZWJ-комбинаций.

### EPUB без сжатия

EPUB ZIP собирается без сжатия. Это корректно, но файлы могут быть больше, чем при использовании полноценного ZIP-сжатия. Для текстовых экспортов это обычно приемлемо.

### Минимальный background

Background почти не участвует в работе. Это хорошо для простоты, но значит, что долгие операции живут в popup. Если popup будет закрыт во время экспорта, операция может быть прервана.

## Тестируемость

Проект уже имеет полезную базу автоматических проверок:

- `scripts/check-project.js` проверяет целостность manifest/runtime-файлов/permissions;
- `scripts/test-extractor.js` запускает extractor в `jsdom` fixtures;
- `scripts/test-epub.js` проверяет структуру EPUB и базовое escaping;
- `npm test` объединяет эти проверки.

Последнее regression-покрытие для extractor моделирует delayed mounting последних двух `conversation-turn-*` после достижения нижней границы. Тест проверяет, что bottom stabilization и DOM quiescence сохраняют финальные сообщения в экспорте.

Наиболее ценные следующие тесты:

- больше fixture-сценариев для изменяющейся DOM-структуры ChatGPT;
- форматирование Markdown/PDF для вложенных списков, таблиц, длинных code blocks;
- regression-тесты на повторяющиеся одинаковые сообщения;
- ручной тест очень длинного чата в актуальном Chrome;
- ручная проверка EPUB в нескольких EPUB-reader приложениях.

## Экспертная оценка

Архитектура прагматичная и соответствует задаче Manifest V3 расширения: content script отвечает за доступ к странице, popup - за пользовательский flow и генерацию файлов, background оставлен минимальным. Самое сильное место - отдельный testable extractor и scroll-aware стратегия для виртуализированных разговоров.

Главная техническая цена - высокая зависимость от DOM ChatGPT и собственные парсеры промежуточного Markdown-like формата. Для расширения без backend и без приватных API это разумный компромисс, но надежность нужно поддерживать регулярными fixture-тестами и ручными проверками после изменений ChatGPT.

Если проект развивать дальше, приоритеты выглядят так:

1. Усилить тесты форматирования PDF/EPUB и edge cases extractor.
2. Явно задокументировать, что экспорт текстовый и не сохраняет изображения.
3. Проверить необходимость `html2pdf.min.js` и `jspdf.min.js` в `lib/`, если они не используются в runtime.
4. Рассмотреть перенос долгих export-операций из popup в более устойчивый flow только если реальные пользователи сталкиваются с прерыванием popup.
5. Не добавлять новые production dependencies до появления конкретного требования, которое нельзя надежно закрыть текущим runtime.
