# 🔀 Git-воркфлоу

## Формат коммитов

Используется формат **Conventional Commits**:

```
<тип>: <краткое описание на русском или английском>
```

### Типы коммитов

| Тип | Назначение | Пример |
|-----|-----------|--------|
| `feat` | Новая функциональность | `feat: добавить экспорт в Markdown` |
| `fix` | Исправление бага | `fix: исправить парсинг вложенных списков` |
| `refactor` | Рефакторинг без изменения поведения | `refactor: вынести парсинг эмодзи в отдельную функцию` |
| `style` | Изменения форматирования/стилей | `style: обновить цвета popup` |
| `docs` | Изменения документации | `docs: обновить README` |
| `chore` | Служебные задачи | `chore: обновить .gitignore` |

## Создание коммитов

Коммиты создаются через временный файл:

```bash
# 1. Создать файл с сообщением
echo "feat: описание изменений" > commit_message.txt

# 2. Закоммитить
git commit -m "feat: описание изменений"

# 3. Удалить временный файл
del commit_message.txt
```

## Ветвление

| Ветка | Назначение |
|-------|-----------|
| `main` | Стабильная версия |
| `feature/<название>` | Разработка новой функции |
| `fix/<название>` | Исправление бага |

## `.gitignore`

Игнорируемые файлы и папки:

```
node_modules/        # npm-зависимости
npm-debug.log*       # Логи npm
.DS_Store            # macOS
Thumbs.db            # Windows
.vscode/             # Настройки IDE
*.log                # Лог-файлы
```

> ⚠️ **Важно:** файлы из `lib/` (pdfmake, html2pdf и др.) **коммитятся** в репозиторий, так как расширение не использует сборщик и зависит от них напрямую.

## Правила

1. **Атомарные коммиты** — один коммит = одно логическое изменение
2. **Осмысленные сообщения** — описание должно быть понятно без контекста
3. **Не коммитить** `node_modules/`, логи, файлы IDE
4. **Проверять** работоспособность расширения перед коммитом
